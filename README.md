## კონკურსის მიმოხილვა
IEEE-CIS Fraud Detection კონკურსის მიზანია საბანკო ტრანზაქციებზე თაღლითობის პროგრონზირება სხვადასხვა ფიჩერებზე, მახასიათებლებზე დაყრდნობით, კერძოდ, მოწყობილობის ტიპის, ბარათის ინფორმაციის, თანხის და სხვა. მონაცემები შედგება ორი ნაწილისგან: Transaction ცხრილი და Identity ცხრილი. პირველ ცხრილში წერია ტრანზაქციის დეტალები, ხოლო მეორეში მომხმარებლის მოწყობილობის ინფორმაცია.  ამ ამოცანას ვაფასებთ area under the ROC curve - მეტრიკის გამოყენებით. 

### მიდგომა ამ ამოცანის გადასაჭრელად
ეტაპობრივად მიდგომას ავირჩევ. გამოვცდი რამდენიმე კლასიფიკაციისთვის შეასაფერის მოდელს, Logistic Regression-ით დავიწყებ და უფრო რთული და კომპლექსური მოდელებისკენ გადავალ. ფიჩერების გადარჩევასაც გავაკეთებ ეტაპობრივად და მერე საბოლოო შედეგის მიხედვით ვნახავ რომელმა გადარჩევებმა გაამართლა ყველაზე კარგად და საუკეთსოს ამოვირჩევ. ანუ მოდელის შედეგებს შევადარებ ROC-AUC მეტრიკით.

## XGBoost
საბოლოოდ გამოვიყენე ყველაზე ძლიერი მოდელი. განსხვავებული prepocessing მაქვს ამ მოდელში. უპირატესობა გვაქვს რომ na მნიშვნელობების შევსება აღარ გვჭირდება ჩვენ, რადგან ეს მოდელი თვითნაც უმკლავდება. null_threshold აქ ავიღე 0.90, ამით შეგვინარჩუნდა უფრო მეტი სვეტი და მოდელმა ბევრად უკეთ შეძლო განზოგადება. ასევე ვცადე კორელაციის ფილტრის გამოყენება, მაგრამ გამიფუჭა შედეგი ამიტომ საერთოდ აღარ ვიყენებ. ამ მოდელს თავისით შეუძლია კატეგორიული ცვლადების რიცხვითში გადაყვანა, ვცადე თუმცა OHE და  WOE უკეთეს შედეგს მაძლევდა ამიტომ საბოლოოდ დავტოვე ეგენი. 

სხვადასხვა კომბინაციები ვცადე პარამეტრების.

| `subsample` | 0.8, 0.9  |
| `learning_rate` | 0.01 , 0.05, 0.1, 0.5 |
| `scale_pos_weight` | 30, 40 |
| `n_estimators` | 100, 250, 300,  400 |

საუკეთსო შედგი მივიღე კომბინაციებით colsample_bytree=0.8, max_depth=6, null_threshold=0.9, subsample=0.8, learning_rate=0.1, scale_pos_weight=30, n_estimators=250
